# Module Handbooks

Shared static website for multiple study programmes. The application code, stylesheets and visual assets are maintained once; each programme provides its own HTML entry point and JSON data.

## Repository structure

- `index.html` – overview of available study programmes
- `GMB/` – Games & Immersive Media programme data and entry point
  - `index.html` – programme entry point with expandable sections for Specifics, Overview (Table 1), Curriculum (Tables 2 and 3), and Details (all module descriptions); module descriptions are rendered when Details is first opened
  - `manifest.json` – semester groups and module references
  - `curriculum.json` – curriculum layout and module positions
  - `modules/*.json` – module data owned by this programme
- `src/*.ts` – shared TypeScript source
- `js/*.js` – browser JavaScript used by the programme entry points
- `assets/css/` and `assets/images/` – shared presentation and media

Future programmes get their own sibling directory, for example `XYZ/`, with the same three programme-specific files and their own `modules/` directory. The application code is not copied.

## Module references

Module references are paths relative to the programme directory, not bare module IDs.

A programme's `manifest.json` contains references such as:

```json
{
  "title": "Semester 1",
  "modules": [
    "modules/code1.json",
    "../XYZ/modules/sharedmodule.json"
  ]
}
```

A programme can therefore use a module owned by another programme without duplicating its JSON file. The path is resolved from the referencing programme's directory.

The keys in `curriculum.json`'s `modules` object must use the exact same references as the manifest. This keeps positions distinct even if two programmes happen to use the same module ID. Each module JSON file's `id` must match its filename without the `.json` extension.

## Programme entry point

Each programme has one `index.html`. Query parameters select the view:

- `index.html` – curriculum overview
- `index.html?view=modules` – module list
- `index.html?module=modules%2Fcode1.json` – module details

Links are generated by the shared rendering code and retain the module's source reference.

## Local preview

Because the browser loads JSON via `fetch()`, do not open the HTML files directly with `file://`. Start a local static server in the repository root, for example:

```sh
npx serve .
```

Then open the local URL printed by the server.

## Editing TypeScript

Install TypeScript if necessary and compile after changing files in `src/`:

```sh
npm install --save-dev typescript
npx tsc -p tsconfig.json
```

The generated files in `js/` are committed as well, so GitHub Pages can serve the site without a build pipeline. Keep `src/` and `js/` synchronized by compiling before publishing.

## Adding a study programme

1. Create a programme directory, e.g. `XYZ/`.
2. Add its `index.html`, using the shared CSS and JavaScript with paths relative to the repository root.
3. Add the programme's `manifest.json` and `curriculum.json`.
4. Put programme-owned module JSON files in `XYZ/modules/`.
5. Use paths in the manifest and as keys in the curriculum positions. Reference another programme's module with a relative path such as `../GMB/modules/code1.json`.

## Publishing on GitHub Pages

Publish the repository root from the `main` branch using **Settings → Pages → Deploy from a branch → main → /(root)**. No Jekyll, Ruby, plugin or server-side build is required.
